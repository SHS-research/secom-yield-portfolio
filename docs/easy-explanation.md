# SECOM 분석 — 쉬운 설명판 (비전공자용)

> 앞의 `portfolio_secom_methodology.md`는 전문용어로 쓴 정식 문서다.
> 이 문서는 **같은 내용을 일상 언어와 비유로** 풀어 쓴 것 + **용어 사전** + **한눈 요약**이다.

---

## 0. 30초 요약 — 내가 한 일 한 문장

> "반도체 공장에서 나온 **센서 기록 1,567건**을 가지고 **어떤 제품이 불량 날지 미리 맞히는 모델**을
> 만들었고, 그 과정에서 **'정확도 높다고 좋은 게 아니다'**를 숫자로 증명하고, 실제 공장에서 쓰려면
> **뭘 조심해야 하는지**(모델이 시간 지나면 낡는다, 비용 기준으로 판단해야 한다)를 밝혀냈다."

---

## 1. 이 데이터가 뭘 나타내나 (비유로)

반도체 공장에서 웨이퍼(반도체 원판)가 라인을 쭉 통과합니다. 그 사이 **590군데에 온도계·압력계
같은 센서**가 붙어 값을 기록해요. 제품 하나가 다 만들어지면 검사에서 **합격(pass) / 불량(fail)**이
찍힙니다.

- **표로 상상하면**: 가로줄 1개 = 제품 1개. 세로칸 590개 = 센서 590개의 측정값. 맨 끝칸 = 합격/불량.
- **총 1,567개 제품**의 기록이 있고, 그중 **불량은 104개(6.6%)** 뿐입니다. → 불량이 매우 드묾.
- 문제는 세 가지:
  1. **불량이 너무 드물다** (100개 중 6~7개) → 그냥 다 "합격"이라 찍어도 대충 맞아버림.
  2. **빈칸(측정 안 된 값)이 많다** — 어떤 센서는 값의 91%가 비어 있음.
  3. **센서 이름이 S0, S1... 처럼 암호** — 이게 온도인지 압력인지 안 알려줌.

---

## 2. 내가 뭘 통해 뭘 분석했나 (쉬운 순서)

1. **빈칸 메우기**: 비어 있는 칸을 그 센서의 "중간값"으로 채웠습니다. (평균 대신 중간값을 쓴 이유는
   §용어사전 '중앙값' 참고 — 튀는 값에 안 흔들리려고)
2. **쓸모없는 칸 버리기**: 항상 똑같은 값만 나오는 센서(고장났거나 안 쓰는 센서)는 버림.
3. **눈금 맞추기**: 어떤 센서는 0~1, 어떤 센서는 0~10000 → 비교가 안 되니 **같은 잣대로 변환**(표준화).
4. **예측 모델 학습**: '랜덤 포레스트'라는 방법으로 "이런 센서값이면 불량 위험 높다"를 학습.
5. **정말 맞는지 검증**: 그냥 맞히는 게 아니라 **여러 각도(통계 검정, 분포 그림, 시간 순서)**로 교차확인.
6. **공장에서 쓸 때 조심할 점 도출**: 시간 지나면 모델이 낡는지, 임계값을 어디 둘지(비용 기준) 등.

---

## 3. 센서가 뭔지 모르는데 어떻게 분석했나 (핵심 아이디어)

센서 이름이 암호라서, **값의 '성격'으로 정체를 추리**했습니다. 사람으로 치면 이름은 몰라도 행동을
보고 "이 사람은 꼼꼼한 성격" 추측하는 것과 같아요.

- 값이 **거의 안 변하면** → "정밀하게 통제되는 설정값"(예: 가스 양 세팅)일 것.
- 값이 **가끔 확 튀면** → "사고성 지표"(예: 먼지·불꽃 횟수)일 것.
- 값이 **넓게 퍼지면** → "막 두께" 같은 결과 measurement일 것.

그리고 **불량 제품과 합격 제품의 센서값 분포를 그림으로 겹쳐**(히스토그램·박스플롯) 봤더니,
**'사고성 지표'(먼지·누설류) 센서에서 불량 제품이 확 튀는** 걸 발견했습니다. 즉 **먼지·이벤트가
튀는 게 불량과 관련**이 크다는 단서.

---

## 4. 가장 중요한 발견 3개 (쉽게)

### 발견 1 — "정확도 93%"는 사기다
누가 "내 모델 정확도 93%!"라고 하면 대단해 보이죠. 그런데 **불량이 원래 6.6%뿐**이라, 아무 생각
없이 **"전부 합격"이라고 찍어도 정확도 93.4%**가 나옵니다. 즉 정확도는 **불량을 하나도 못 잡아도
높게 나오는 가짜 성적표**예요. 그래서 저는 **불량을 실제로 얼마나 잡는지**를 재는 다른 점수(PR-AUC)를
썼고, 진짜 실력은 **무작위 찍기의 3.6배** 수준이었습니다.

### 발견 2 — 모델은 시간이 지나면 낡는다
데이터를 **아무렇게나 섞어서** 시험 보면 성적이 좋게(0.21) 나옵니다. 그런데 **"과거로 배우고 미래를
맞혀라"**(실제 공장 상황)로 시험 보면 성적이 **0.06으로 폭락** — 거의 찍기 수준. → **공정이 시간에
따라 조금씩 변해서**, 한 번 만든 모델을 계속 쓰면 안 되고 **주기적으로 다시 학습**시켜야 한다는 뜻.
이건 실제 공장 운영에서 아주 중요한 교훈이에요.

### 발견 3 — "불량 놓치는 손해 vs 헛검사 손해"로 판단해야
모델은 "불량일 확률 몇 %"를 줍니다. 보통 50% 넘으면 불량으로 치는데, 반도체는 **불량 하나 놓치면
손해가 훨씬 큼**(불량이 뒷공정까지 흘러감). 그래서 기준선을 50%가 아니라 **8%로 낮춰**(조금만
의심돼도 걸러냄) 계산했더니 **전체 손해비용이 38% 줄었습니다**. → 정답률이 아니라 **돈(비용)으로
판단**하는 게 공장 방식.

## 5. 기존(남들 방식)보다 뭐가 더 좋은가 — 요약표

| 항목 | 보통 사람들이 하는 것 | 내가 더 한 것 | 왜 더 좋은가 |
|---|---|---|---|
| 성적 재는 법 | "정확도" 자랑 | 불량 잡는 점수(PR-AUC) | 정확도는 불량 못 잡아도 높게 나오는 가짜 |
| 시험 방식 | 데이터 막 섞어 시험 | 과거→미래 순서로 시험 | 실제 공장 상황과 같음, 낡음을 발견 |
| 불량 데이터 부족 처리 | 무조건 'SMOTE' 기법 | SMOTE가 실제로 안 좋음을 검증 | 유행 기법을 맹신 안 하고 데이터로 확인 |
| 합/불 판단 기준 | 무조건 50% | 비용으로 최적점 계산 | 손해비용 38% 절감 |
| 중요 센서 관리 | 한 번 정하고 고정 | 시간 지나면 바뀜을 발견 | 잘못된 센서만 계속 볼 위험을 경고 |

**한 줄 결론**: 남들은 "모델 잘 맞혀요"에서 끝나지만, 저는 **"실제 공장에 갖다 쓰면 어떻게 될까"**까지
따져서, 함정(가짜 정확도)·수명(낡음)·비용(운영 기준)을 **숫자로** 밝혔습니다. 이게 **양산기술 엔지니어가
실제로 고민하는 문제**와 똑같습니다.

## 6. 용어 사전 (자주 나온 말)

| 용어 | 쉬운 뜻 |
|---|---|
| **런(run) / 샘플** | 제품(웨이퍼 로트) 한 개의 기록 한 줄 |
| **특성(feature) / 센서** | 측정 항목 하나 (세로칸 하나) |
| **라벨(label)** | 정답. 여기선 합격(pass)/불량(fail) |
| **결측치(missing)** | 값이 비어 있는 칸 |
| **대치(imputation)** | 빈칸을 그럴듯한 값으로 채우는 것 |
| **중앙값(median)** | 값들을 줄 세웠을 때 딱 가운데 값. 극단값에 안 흔들려서 평균보다 안전 |
| **표준화(standardize)** | 눈금 제각각인 값들을 같은 잣대로 맞추는 것 |
| **불균형(imbalance)** | 합격은 많고 불량은 적어 한쪽으로 쏠린 상태 |
| **정확도(accuracy)** | 전체 중 맞힌 비율. 불균형이면 가짜로 높아짐 |
| **PR-AUC** | 드문 것(불량)을 실제로 얼마나 잘 잡는지 재는 점수. 불균형에 적합 |
| **ROC-AUC** | 비슷한 성적표지만, 불균형에선 실제보다 좋게 보이는 함정 있음 |
| **랜덤 포레스트** | 여러 개의 '스무고개 나무'를 모아 다수결로 예측하는 방법. 강력하고 해석 가능 |
| **SMOTE** | 부족한 불량 데이터를 인공으로 늘리는 기법 (여기선 효과 없었음) |
| **class_weight** | 드문 불량에 '가중치'를 줘서 모델이 무시 못 하게 하는 방법 |
| **드리프트(drift)** | 시간이 지나며 공정/데이터가 조금씩 변하는 현상 |
| **재학습(retrain)** | 낡은 모델을 새 데이터로 다시 훈련시키는 것 |
| **임계값(threshold)** | 확률 몇 % 넘으면 '불량'이라 볼지 정하는 경계선 |
| **운영점** | 실제 사용할 임계값 (비용을 고려해 정함) |
| **효과크기(effect size)** | 두 그룹 차이가 '얼마나 큰지'의 정도 |
| **p값 / FDR** | 그 차이가 우연이 아닐 가능성. 작을수록 '진짜 의미있는' 차이 |
| **다중공선성** | 두 센서가 거의 같은 정보 (중복). 하나만 남기면 됨 |
| **SPC / 관리도** | 공정이 안정적인지 시간에 따라 감시하는 공장 표준 도구 |
| **히스토그램** | 값이 어디에 몰려있는지 막대로 보여주는 분포 그림 |
| **박스플롯** | 값의 가운데·퍼짐·튀는 값(이상치)을 상자로 요약한 그림 |
