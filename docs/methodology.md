# SECOM 분석 방법론 — 데이터·처리·원리 상세

> 이 문서는 "어떤 데이터를, 어떤 메커니즘으로, 어떤 원리에 근거해" 분석했는지를 단계별로 기록한다.
> 모든 수치는 `secom_analysis.py` / `secom_drift.py` / `secom_advanced.py` / `secom_eda.py` 실행
> 결과에서 나온 실측값이다(재현: `python <파일명>`).

---

## 1. 어떤 데이터인가

- **출처**: UCI SECOM (반도체 웨이퍼 제조 계측 데이터, 실제 fab 라인).
- **규모**: 1,567 런(생산단위) × 590 센서 + pass/fail 라벨 + 타임스탬프(2008-07-19 ~ 10-17, 약 3개월).
- **성격**: 각 런은 웨이퍼 로트가 라인을 통과하며 590개 계측 지점에서 찍힌 값. 라벨 −1=pass, 1=fail.
- **익명화**: 센서명이 `S0..S589`로 익명. → 물리적 정체를 모르므로, **통계적 지문으로 공정 파라미터
  부류를 가정**하는 접근이 필요(§5).
- **핵심 난점 3가지**: (a) 불량 6.6%의 **극심한 불균형**, (b) 전체 셀 4.5% + 특정 센서 최대 **91% 결측**,
  (c) 590차원 **고차원**(런 1,567개보다 많은 특성 → 차원의 저주).

## 2. 어떤 메커니즘으로 품질을 예측했는가 (파이프라인)

원 데이터 → **[결측 대치] → [상수열 제거] → [표준화] → [분류기]** 순서의 sklearn `Pipeline`.
파이프라인으로 묶은 이유: 교차검증 시 **각 fold의 학습데이터로만** 대치·표준화 통계를 계산해
**데이터 누수(leakage)를 차단**하기 위함(테스트 정보가 전처리에 새면 성능이 낙관적으로 부풀음).

```
SimpleImputer(median) → VarianceThreshold(0) → StandardScaler → RandomForest(class_weight)
```

- 예측 산출물은 이진분류(pass/fail)가 아니라 **불량 확률 `predict_proba`** → 임계값을 나중에
  비용 기준으로 조정(§6, 운영점).

## 3. 결측치 · 특성선택 · 불균형 — 각각 어떻게

### 3-1. 결측치 처리 (Missing Value)
- **채택 방법**: 중앙값(median) 대치 (`SimpleImputer(strategy="median")`).
- **평균/중앙값/KNN 실측 비교** (`secom_impute_compare.py`, 같은 모델·분할, 지표 PR-AUC):

  | 대치법 | CV PR-AUC | test PR-AUC | 판단 |
  |---|---|---|---|
  | 평균(mean) | 0.209 ± 0.048 | 0.223 | 왜도에 끌려 test 최저 |
  | **중앙값(median)** | 0.206 ± **0.038** | 0.235 | **오차 최소=가장 안정**, 강건, 빠름 → 채택 |
  | KNN(k=5) | 0.225 ± 0.060 | 0.237 | CV 살짝 높지만 오차 최대·느림·불안정 |

  → **세 방법 차이는 오차범위 안**(신뢰구간 겹침)이라 "KNN이 최고"라 단정하지 않는다. 평균은
  왜도 큰 센서(파티클·누설 카운트류)에서 이상치에 끌려 왜곡되고, KNN은 590차원 거리계산이
  느리고 **최대 91% 결측 센서**엔 이웃이 신뢰 불가. **중앙값이 강건·재현성(오차 최소)·속도**에서
  균형이 좋아 실무 기본값으로 채택.
- **결측을 '신호'로도 봄 (실측 검증, `secom_missing.py`)**: 특정 센서 결측률 최대 91% → 결측 자체가
  "그 계측을 건너뛴 공정 경로"를 뜻할 수 있음. 실제로 (a) 결측 **개수**는 불량과 무관(pass 26.9 vs
  fail 25.5, p=0.35)이나, (b) 결측 **위치 패턴만으로** PR-AUC 0.122(무작위 0.066의 ~2배)로 신호가
  있고, (c) **대치 + 결측 플래그**(`add_indicator=True`)가 대치만보다 우수(**0.235 → 0.251**).
  → "빈 칸을 그냥 채우지 말고, 비었다는 사실을 특성으로 남겨라"가 데이터로 확인됨.

### 3-2. 특성선택 (Feature Selection) — **두 경로를 교차검증**
1. **분산 필터**: `VarianceThreshold(0.0)`로 상수열(변동 0인 미사용 채널) 제거.
2. **모델 기반**: RandomForest **feature importance** 상위 → S59, S103, S33, S477, S64.
3. **가설검정 기반(추가 도입)**: pass/fail 두 그룹의 분포차를 **Mann-Whitney U 검정**(정규성 가정
   없는 비모수)으로 검정, **Benjamini-Hochberg FDR**로 다중검정 보정 → **470센서 중 21개가
   FDR<0.05로 유의**. 상위: S59(p_fdr=2.67e-08), S103, S247, S519, S510, S477.
- **교차 일치**: 모델 기반(S59·S103·S477)과 가설검정 기반 상위가 **겹침** → 서로 다른 원리의 두
  방법이 같은 센서를 지목 = **신뢰도 높은 특성선택**.
- **다중공선성 제거**: 상위센서 상관 히트맵에서 **S247–S519(r=0.97), S477–S205(r=0.99)** = 중복정보.
  → 쌍에서 하나만 남기면 모델이 간결·안정.

### 3-3. 불균형 처리 (Imbalance) — **통념(SMOTE)을 검증 후 기각**
- **1차 선택**: `class_weight="balanced_subsample"` — 손실함수에서 소수클래스(불량)에 가중.
- **SMOTE와 실측 비교**: 합성 오버샘플링 SMOTE를 붙여 비교 → PR-AUC 이득이 **−0.033(무작위분할)**,
  **−0.004(시간순분할)**로 오히려 나쁨. → "불균형이면 무조건 SMOTE"라는 통념을 **데이터로 기각**,
  class_weight 채택.
- **왜 SMOTE가 여기서 안 통하나**: SMOTE는 소수샘플 사이를 보간해 합성점을 만드는데, 590차원
  고차원에서 보간점이 실제 불량 분포를 대표하지 못하고 **결정경계만 낙관적으로 부풀림**. 시간순
  검증에서 이득이 사라지는 게 그 증거.

| 구분 | 남들이 하는 것 | 내가 추가 도입 | 그래서 새로 안 것 (수치) |

## 5. 각 feature = 어떤 공정 파라미터인가 (가정) + 분포 파악

센서가 익명이므로, 각 센서의 **통계적 지문(변동계수 CV·왜도·첨도·시간드리프트)**으로 fab 공정
파라미터 '부류'를 공학적으로 가정(`classify_sensor()`):

| 통계적 지문 | 가정한 공정 파라미터 부류 |
|---|---|
| CV<0.01 (거의 상수) | 초정밀 제어값 (MFC 가스유량·압력 셋포인트) |
| CV 0.01~0.1, 종모양 | 안정 아날로그 계측 (온도·압력·RF 파워) |
| 왜도>3 (우편향 롱테일) | 카운트/이벤트성 (파티클·누설·아크 카운트) |
| 첨도<−1 (이봉/평탄) | 이봉·다봉 (챔버·레시피·설비 간 차이) |
| CV≥0.1 (광변동) | 막두께·증착률·유효면적류 |

**히스토그램·박스플롯으로 파악한 것** (상위 6센서, pass vs fail 겹쳐 그림):
- **히스토그램**(`secom_eda_hist.png`): pass/fail 밀도를 겹쳐, 불량군의 분포가 어느 쪽으로
  치우쳤는지 확인. 최상위 **S59**(파티클/이벤트성 가정)는 불량군에서 꼬리가 두꺼움 → 이벤트
  급증이 불량과 동반.
- **박스플롯**(`secom_eda_box.png`): pass/fail 중앙값·IQR·**IQR 이상치 개수**를 병기. 불량군에서
  이상치가 더 많이 찍히는 센서 = 공정 산포가 커진 지점.
- **효과크기**로 정량화: S59의 rank-biserial 효과크기 0.38 = pass/fail 분포가 뚜렷이 분리.

즉 "어떤 센서가 불량과 관련되나"를 **모델(RF) + 눈으로 보는 분포(히스토/박스) + 통계검정(U/FDR)**
세 각도로 삼각검증했다.

## 6. 정확도가 높은 알고리즘이 왜 '좋은 게 아닌지' — 통계적 원리

### 6-1. 정확도의 함정 = 기저율(base rate) 지배
- 정확도 = (TP+TN)/N. 음성(pass)이 **93.4%**면, **아무것도 안 하고 전부 pass로 찍는 분류기도
  정확도 93.4%**. 즉 정확도는 다수클래스(TN)에 지배되어 **소수클래스(불량) 판별력을 전혀 반영 못 함**.

### 6-2. 왜 PR-AUC인가 (ROC-AUC의 함정까지)
- **ROC-AUC**는 FPR=FP/(FP+**TN**)을 쓰는데, TN이 압도적이면 FP가 늘어도 FPR이 거의 안 커져
  **불균형에서 낙관적**. 실제로 RF의 ROC-AUC는 0.810으로 좋아 보이지만,
- **PR-AUC**는 정밀도=TP/(TP+FP)로 **TN을 안 쓰고 소수클래스만** 본다 → RF PR-AUC 0.235.
  무작위 기준 PR-AUC는 불량률 그 자체(0.066)이므로, **0.235는 무작위의 3.6배**가 진짜 성능.

### 6-3. 왜 무작위분할이 성능을 부풀리나 = 독립성 가정 위반
- 무작위분할은 "샘플이 i.i.d.(독립동일분포)"를 가정. 그러나 공정은 **시간 순서로 드리프트**하므로
  이 가정이 깨진다. 무작위분할은 미래 데이터를 학습에 섞어 **미래를 이미 본 낙관적 추정**.
- 시간순 분할(과거로 학습→미래 예측)이 실제 배포 조건 → PR-AUC 0.063으로 붕괴 = **분포 이동
  (concept drift)**의 통계적 증거. 그래서 "정확도/AUC 높음"이 아니라 **"언제까지 유효한가"**가 핵심.

## 7. 어떤 데이터가 양산기술·내 연구를 가장 잘 설명하나

- **양산기술 직무 설명력**: SECOM이 가장 직결. 이유 — 실제 라인의 다센서·불량라벨·시계열이라
  **수율예측·이상탐지·드리프트·SPC**를 모두 실증 가능. (내 ALD 증착 데이터 254런은 너무 깨끗해
  이상탐지 수치가 안 나옴 → 그 공백을 SECOM이 메움.)
- **내 연구(ALD) 연결**: SECOM의 "결측=경로", "센서 드리프트=소모품 열화" 관점은 내 **PM/BM
  설비관리·RCA 작업**(`rca_core.py` 등)과 동일한 사고방식. 즉 SECOM으로 익힌 드리프트·재학습·
  비용운영점 개념을 내 설비/공정 데이터에 이식할 수 있음.
- **역할 분담**: SECOM=수율/이상탐지(공정), Bosch=대량 불량/공정경로(라인), WM-811K=웨이퍼 불량
  패턴의 **공간 통계**(소자/수율맵). 세 개가 양산의 서로 다른 축을 커버.

## 8. Raw data를 어떻게 가공했는가

1. **로딩**: `secom.data`는 공백구분·헤더없음 → `sep=r"\s+", header=None`, `NaN` 문자열을 결측 처리.
   컬럼을 `S0..S589`로 명명.
2. **라벨 파싱**: `secom_labels.data`의 `"<label> <timestamp>"`를 분리 → 라벨은 fail=1/pass=0으로
   재코딩(소수클래스를 양성 1로 두어 재현율·정밀도 해석을 직관화), 타임스탬프는 `datetime` 변환.
3. **정합성**: 상수열 제거(분산 0), 중앙값 대치, 표준화(평균0·분산1) — 스케일이 제각각인 590센서를
   같은 축으로.
4. **시간축 가공**: 타임스탬프를 주(week) 단위 `resample`하여 **주간 불량률·센서 주간평균**을 생성
   (p-관리도·드리프트 분석용).

## 9. 데이터마이닝으로 끄집어낸 지식 (요약)

1. **정확도 93.4%는 무의미**, 실 판별력은 PR-AUC 0.235(무작위의 3.6배).
2. **모델은 시간이 지나면 죽는다** — 시간순 PR-AUC 0.063 → **재학습 주기 설계가 양산 필수**.
3. **불량은 이벤트성 센서(S59 등 파티클·누설류)와 가장 관련** — 통계검정·모델·분포 3각 일치.
4. **상위 센서는 시간에 따라 바뀐다**(Jaccard 0.03) — "고정 센서 관리"는 위험, 재평가 체계 필요.
5. **SMOTE는 만능이 아니다** — 여기선 class_weight가 우세.
6. **최적 운영점은 정확도가 아니라 비용** — 임계값 0.08에서 총비용 38% 절감.
7. **공정은 통계적으로 불안정** — p-관리도 관리상한 이탈 주가 존재.

## 10. 어떤 학습 알고리즘으로 분석했는가

| 알고리즘 | 역할 | 선택 이유 |
|---|---|---|
| **RandomForest** (주력) | 불량 확률 예측·피처 중요도 | 비선형·고차원·결측/스케일에 강건, 중요도로 해석 가능 |
| **LogisticRegression**(bal) | 선형 베이스라인 | RF의 이득이 '모델 덕'인지 '데이터 한계'인지 대조군 |
| **Mann-Whitney U + BH-FDR** | 가설검정 특성선택 | 비모수(정규성 불요), 다중검정 보정으로 거짓양성 억제 |
| **SMOTE**(비교용) | 불균형 처리 대조 | 통념 검증(채택이 아니라 기각의 근거로 사용) |
| **p-관리도(SPC)** | 시간축 공정안정성 | 양산 표준 관리도 언어로 드리프트 제시 |

**총평**: 단일 "정확도 높은 모델"을 자랑하는 대신, 서로 다른 원리의 알고리즘으로 **삼각검증**하고
**양산 배포 조건(시간·비용·안정성)에서 재평가**한 것이 이 분석의 방법론적 차별점이다.
